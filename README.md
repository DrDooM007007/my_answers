2. Git – это специальная программа, которая позволяет отслеживать любые изменения в файлах, хранить их версии и оперативно возвращаться в любое сохранённое состояние.
Большинство других систем контроля версий хранят информацию в виде списка изменений в файлах. Git работает иначе — он хранит скорее набор снимков — полное отображение того, как выглядит файл в момент сохранения. Это позволяет всегда иметь полную информацию обо всех файлах и быстро восстанавливать любую из предыдущих версий.
Есть проект, в котором пишется код. В нём создано окружение Git ― все изменения файлов отслеживаются в рамках настроенных параметров и заданных фильтров. Нужно добавить в проект новую функцию, изменив или доработав существующий код. Для этого потребуется создать внутри проекта отдельную ветку — в Git они называются branch. Работа в этой ветке никак не затрагивает основной код — если с новыми изменениями что-то пойдёт не так и код станет невалидным и перестанет запускаться, основной проект не пострадает. А когда новая функция будет дописана и протестирована, ветку можно будет «наложить» на основной код.
Также в рамках Git можно объединять разные версии кода в один. Например, над проектом трудится несколько программистов, и каждый разрабатывает или изменяет код в собственных ветках. В конце работы появится необходимость слить ветки вместе — и получается цельная программа. Это значительно облегчает совместную работу, так как не нужно ждать, пока другой разработчик допишет код, — можно работать параллельно.
Если же в одной из веток разработка пойдёт не по плану и произойдёт ошибка — всё можно просто откатить до предыдущей ветки в системе контроля версий Git, где ошибок не было. И начать разработку заново.
Git может быть локальным, централизованным или распределённым:
Локальный установлен на одном компьютере и хранит файлы только в одном экземпляре в рамках настроенного окружения — подходит, если программист пишет код в одиночку.
Централизованный находится на общем севере и хранит все файлы на нем.
Распределённый хранит данные и в общем облачном хранилище, и в устройствах участников команды.
Распределённая система лучше всего подходит для командной работы. Даже если с центральным хранилищем что-то случится, проект можно восстановить из копий участников команды.
Основные команды для работы с Git :
git commit — фиксация изменений;
git diff — просмотр актуальных или предыдущих изменений в рамках работы над репозиторием;
git checkout — переход на предыдущее состояние или ветку;
git push/pull — отправка и получение изменений из удалённого репозитория;
git stash — сохранение изменений в архив для последующего использования.
4. GitOps — это подход к управлению ИТ-инфраструктурой и серверами, при котором вся конфигурация системы хранится в Git-репозитории, 
а специальная программа автоматически делает так, чтобы реальный сервер всегда точно соответствовал этому описанию.
Как это работает простыми словами
Единый источник правды: Git (система хранения кода) становится главным документом, где написано, как именно должны работать ваши сайты или приложения.
Никаких ручных правок: Администраторы больше не заходят на серверы вручную, чтобы изменить настройки.
Автоматическая сверка: Специальный робот-агент внутри системы постоянно сравнивает то, что записано в [Git], с тем, что происходит на сервере в реальности.
Исправление ошибок: Если кто-то случайно сломает настройки на самом сервере, робот заметит это, сотрет изменения и вернет всё 
в безопасное состояние из [Git].

5. Семантическое версионирование — это единый международный стандарт для присвоения номеров версий программам. Этот подход позволяет разработчикам и пользователям сразу понять, какие изменения произошли 
в коде, просто взглянув на цифры.
В Git это используют при создании меток (git tags), чтобы зафиксировать конкретное состояние проекта (например, релиз).
Каждая версия состоит из трех чисел, разделенных точками: МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ (например, v1.4.2).
Каждая цифра имеет строгий смысл и меняется по своим правилам:
ПАТЧ (Patch) — исправление ошибок.
Когда меняется: Если вы починили баг, оптимизировали код или исправили опечатку, не добавляя новых функций.
Пример: 1.4.2 превращается в 1.4.3.
Безопасность: Абсолютно безопасно для обновления.
МИНОРНАЯ (Minor) — новый функционал.
Когда меняется: Если вы добавили новую фичу, кнопку или возможность, но при этом всё старое продолжает работать так же, как раньше (сохранена обратная совместимость).
Пример: 1.4.2 превращается в 1.5.0 (счетчик патчей при этом сбрасывается в ноль).
Безопасность: Безопасно, ничего не должно сломаться.
МАЖОРНАЯ (Major) — кардинальные изменения.
Когда меняется: Если вы переписали код так, что старые функции больше не работают, удалили что-то важное или изменили логику работы (обратная совместимость нарушена). Пользователям придется переписывать свой код под вашу новую версию.
Пример: 1.4.2 превращается в 2.0.0 (минорная версия и патч сбрасываются в ноль).
Безопасность: Требует осторожности, проект может «сломаться» после обновления.
6. Что такое Dockerfile? Dockerfile — это текстовый файл с инструкциями для сборки Docker-образа, как рецепт для повара. В нём описывается: какую базовую систему использовать (например, ubuntu или alpine); какие зависимости установить; какие файлы скопировать в контейнер; какие команды выполнять при запуске.
Зачем он нужен? Автоматизация сборки Вместо того чтобы вручную устанавливать зависимости и настраивать окружение, вы один раз описываете процесс в Dockerfile. После этого образ можно пересобрать где угодно — результат будет одинаковым. Повторяемость С Dockerfile ваше приложение всегда запускается в одном и том же окружении. Это решает классическую проблему «у меня работает, а у тебя нет». Переносимость Образ, собранный по Dockerfile, можно запускать на любой машине, где установлен Docker: Linux, Windows, macOS или сервер в облаке. Удобство для команды Команда разработчиков получает единый способ запуска приложения. Неважно, у кого какая ОС и версия Python — Dockerfile гарантирует одинаковую среду. Инфраструктура как код Dockerfile можно хранить в Git вместе с проектом. Это значит, что история изменений окружения будет такой же прозрачной, как история кода. Docker — это программная платформа для автоматизации упаковки, запуска и управления приложениями в изолированных контейнерах. Главная идея и зачем он нужен. Изоляция: программа упаковывается вместе со всеми своими библиотеками и настройками в единый контейнер. Предсказуемость: приложение работает одинаково на любом компьютере и сервере («у меня на компьютере всё работает» больше не проблема). Экономия ресурсов: Контейнеры делят одно ядро операционной системы, поэтому они работают быстрее и весят меньше, чем полноценные виртуальные.
Как без Docker раньше жили: Виртуальные машины (VM): Использовали VMware, VirtualBox или KVM. Но виртуальная машина «тяжелая»: она требует полноценную 
ОС внутри себя, гигабайты диска и гигабайты оперативной памяти. Из-за этого на одном физическом сервере нельзя было запустить много изолированных сервисов — не хватало ресурсов. Каждое развертывание приложения было стрессом. Системные администраторы вручную писали длинные инструкции (чек-листы) по настройке серверов. На дело могли уходить часы, а иногда и дни, пока команда вручную сопоставляла версии библиотек и искала, почему код ведет себя иначе.
7. 1. ls– Отображение содержимого каталога: полезно для просмотра файлов и папок, проверки прав доступа к файлам, прав собственности и скрытых файлов.
cd– Смена каталога: Позволяет перемещаться между каталогами для выполнения задач в нужном месте.
mkdir– Создание каталогов: помогает в организации файлов проекта и создании необходимой структуры папок.
rm– Удаление файлов и папок: Используется для удаления файлов или каталогов, но следует проявлять осторожность при использовании во избежание повреждения системы.
cat– Просмотр содержимого файла: отображает содержимое файла, что полезно для быстрой проверки файлов конфигурации или журналов.
grep– Поиск текста в файлах: фильтрует строки, соответствующие заданному шаблону, идеально подходит для поиска в логах и коде по определенным ключевым словам.
echo– Отображение текста или переменных: Выводит сообщения или записывает содержимое в файлы, что полезно для отладки и создания файлов.
chmod– Изменение прав доступа к файлам: Изменяет права доступа к файлам, позволяя выполнять скрипты.
ps– Просмотр активных процессов: отображает запущенные процессы, что полезно для проверки состояния программы и устранения неполадок.
sudo– Выполнение команд от имени root: Предоставляет права суперпользователя для выполнения административных задач, таких как установка программного обеспечения и настройка системы.
8. Сетевые порты TCP и UDP — это числовые идентификаторы 
(от 0 до 65535), которые помогают операционной системе понять, какому именно приложению или службе на компьютере адресован входящий сетевой пакет.
Главные отличия протоколов
TCP (Transmission Control Protocol): Надежный протокол 
с установлением соединения. Он проверяет, дошли ли все пакеты, 
и запрашивает их повторно при потере. Работает медленнее.
UDP (User Datagram Protocol): Быстрый протокол без подтверждения доставки. Он отправляет данные сразу, даже если часть из них потеряется 
по пути.
9. По версии протокола
IPv4: Старый и самый распространенный формат, состоящий из четырех чисел от 0 до 255 (например, 192.168.1.1). Количество адресов ограничено примерно 4,2 миллиардами.
IPv6: Новый стандарт, использующий 128-битную запись 
из шестнадцатеричных символов (например, 2001:db8::1). Создан для решения проблемы нехватки IPv4-адресов.
По способу назначения
Статический: Постоянный адрес, который не меняется при перезагрузке роутера или переподключении к сети. Его вручную настраивают или закрепляют за устройством у провайдера. Удобен для удаленного доступа 
и хостинга.
Динамический: Адрес, который автоматически выдается устройству 
из пула провайдера или роутера при каждом новом подключении 
и со временем может измениться. Используется большинством провайдеров для экономии адресного пространства.
10. NAT (network address translation) — это технология, позволяющая перенаправлять трафик между локальной и глобальной сетями. Благодаря ей устройства могут не только взаимодействовать друг с другом в домашней сети, но и выходить в интернет.
Это нужно по трём основным причинам:
Экономия IP-адресов. Количество свободных IP-адресов в мире ограничено, а оборудование, способное выдержать столько независимых линий, стоит очень дорого. Чтобы не выдавать каждому устройству, подключённому к Глобальной сети, свой собственный IP адрес, проще предоставить клиенту один основной, к которому через маршрутизатор можно подключить множество гаджетов.
Безопасность. NAT скрывает локальные IP-адреса от внешней сети, обеспечивая дополнительный уровень конфиденциальности. Современные маршрутизаторы также позволяют вручную настраивать NAT, поэтому можно запретить некоторым устройствам выходить в интернет или посещать определённые сайты.
Удобство. NAT позволяет устройствам обмениваться данными в локальной сети без необходимости подключения к интернету, одновременно обеспечивая доступ к ресурсам Глобальной сети.

11. Отличие публичного от приватного адресов.
Публичный (белый): Уникальный глобальный адрес, который виден 
во всем интернете. Нужен для запуска серверов, сайтов или организации прямых подключений (например, в некоторых онлайн-играх).
Приватный (серый / внутренний): Используется внутри локальных сетей (домашних, офисных). Такие адреса повторяются в разных локальных сетях, 
а в интернет выходят через один общий публичный адрес роутера с помощью технологии NAT.
12. Главные отличия переменных в Bash и Python
Объявление и пробелы
Bash: Присваивание пишется без пробелов вокруг знака равенства (name=value). Если поставить пробел (name = value), Bash выдаст ошибку.
Python: Присваивание использует пробелы по стандартам стиля PEP 8 (name = value).
Обращение к значению
Bash: Чтобы получить значение переменной, нужно поставить знак доллара перед именем — $name или ${name}.
Python: Используется просто имя переменной без знака доллара — name.
Типизация
Bash: Все переменные по умолчанию являются строками.
Python: Переменные имеют полноценные типы данных (int, float, str, list и др.), которые определяются автоматически.
13. Условия и циклы в Bash и Python управляют ходом выполнения кода, но имеют разный синтаксис и логику работы.
Условный оператор if
Bash: Использует квадратные скобки [...] или [[...]] для проверки условий, а блок кода завершается ключевым словом fi (if наоборот).
Python: Использует отступы и двоеточие :, а вместо else if применяется сокращение elif.
Цикл for
Bash: Работает как итератор по списку слов или элементов, используя конструкции in и слова do/done.
Python: Перебирает любые коллекции (списки, диапазоны range()) с помощью конструкции for ... in.
Цикл while
Bash: Выполняет код, пока команда или условие возвращают истину (код возврата 0), используя блоки do/done.
Python: Выполняет блок кода, пока логическое выражение истинно (True).
14. Функция в Python — это именованный блок кода, который выполняет определенную задачу и может многократно использоваться в разных частях программы.
Создание и вызов функции.
Функции определяются с помощью ключевого слова def, за которым следуют имя функции, круглые скобки и двоеточие.
Синтаксис: Тело функции пишется с отступом (обычно 4 пробела).
Аргументы: Данные, которые передаются внутрь функции через круглые скобки.
Возврат значения: Инструкция return возвращает результат работы функции наружу.
15. Модуль в Python — это отдельный файл с расширением .py, который содержит код для повторного использования в других программах.
Что такое модуль и зачем он нужен
Файл с кодом: Любой файл Python может быть модулем.
Повторное использование: Позволяет не писать один и тот же код заново.
Разделение логики: Помогает структурировать большие проекты 
на части.
Встроенные возможности: Стандартная библиотека Python содержит сотни готовых модулей (например, math, random, datetime).
Пустой файл __init__.py сообщает интерпретатору Python, что папка, 
в которой он находится, является пакетом (библиотекой модулей).
Зачем нужен пустой __init__.py
Маркер пакета: Позволяет использовать точечную нотацию для импорта (from my_package import my_module).
Предотвращение конфликтов: Защищает случайные совпадения имен папок со стандартными библиотеками Python.
Совместимость: Гарантирует правильную работу импорта во всех старых и новых версиях Python, а также во внешних инструментах.
16. Команда set в Bash изменяет параметры оболочки (опции) и управляет позиционными аргументами, а также выводит список всех переменных 
и функций, если запустить её без аргументов.
Главные задачи команды set
Изменение режимов выполнения: Настройка безопасного поведения скриптов с помощью флагов.
Управление позиционными параметрами: Передача значений аргументов ($1, $2 и т.д.).
Просмотр переменных: Вывод списка всех текущих переменных 
и их значений при вызове без аргументов.
17. Команда strace в Linux — это диагностическая утилита, которая перехватывает и записывает системные вызовы (сисколлы) и сигналы, проходящие между процессом и ядром операционной системы.
Зачем нужна strace
Поиск ошибок: Помогает понять, почему программа падает, не может найти файл или открыть порт.
Отладка: Показывает, какие именно запросы приложение отправляет ядру.
Анализ работы: Позволяет увидеть реальные пути к конфигурационным файлам и библиотекам, которые открывает программа.
18. Команда lsof (сокращение от List Open Files) — это мощная утилита командной строки в Linux и Unix-подобных системах, которая показывает список всех файлов, открытых запущенными процессами.
В Unix-подобных системах «всё является файлом»: обычные файлы, каталоги, сетевые сокеты, каналы (pipes) и устройства. Поэтому lsof полезна не только для работы с файлами, но и для анализа сети.
Основные возможности
Поиск процессов: Узнать, какой именно процесс использует конкретный файл или папку.
Работа с сетью: Посмотреть, какие программы занимают определенные сетевые порты или держат открытыми сетевые соединения.
Диагностика дисків: Выяснить, какой процесс мешает размонтировать файловую систему или удалить занятый файл.
19. Shebang — это специальная строка #! в самом начале исполняемого файла или скрипта, которая указывает операционной системе, какой интерпретатор нужно использовать для её запуска.
Как устроен Shebang
Строка должна находиться на самом первом месте в файле.
Она всегда начинается с символов #! (называется также hashbang).
За символами следует полный путь к программе-интерпретатору.
20. Точкой входа в Python называют конструкцию if __name__ == "__main__":, с которой начинается выполнение скрипта при его прямом запуске.
21. Модуль argparse позволяет разбирать аргументы, передаваемые скрипту при его запуске из командной строки, и даёт возможность пользоваться этими аргументами в скрипте. То есть речь идёт о том, что этот модуль позволяет предоставлять скрипту некие данные в момент его запуска, а этими данными скрипт сможет воспользоваться во время выполнения его кода. Модуль argparse — это средство, с помощью которого можно наладить общение между автором программы и тем, кто ей пользуется, например — между вами, когда вы сегодня пишете скрипт, и вами же, когда вы завтра его запускаете, что-то ему передавая.
Использование argparse означает, что, при необходимости изменить поведение скрипта или при необходимости передачи ему неких данных, если это предусмотрено автором скрипта, пользователю не нужно редактировать программный код. В результате скрипты обретают определённый уровень гибкости.
22. Корневой каталог / в Linux — это отправная точка всей файловой системы, где собраны все файлы и папки. Их структура стандартизирована стандартом FHS (Filesystem Hierarchy Standard).
Основные корневые директории и их назначение:
/bin — основные исполняемые файлы (программы) для всех пользователей, нужные для работы системы и в однопользовательском режиме (например, ls, cat, bash).
/sbin — системные исполняемые файлы и утилиты, предназначенные преимущественно для администратора (root) (например, fdisk, reboot, iptables).
/etc — общесистемные файлы конфигурации программ и служб (например, passwd с данными пользователей, настройки сети).
/home — домашние каталоги пользователей (например, /home/user), где хранятся их личные файлы и настройки.
/root — домашняя папка суперпользователя (root).
/lib, /lib64 — системные библиотеки (драйверы и модули), необходимые для работы программ из /bin и /sbin.
/usr — вторичная иерархия для пользовательских программ и данных (содержит собственные подкаталоги /usr/bin, /usr/sbin, /usr/lib и т. д.).
/var — изменяемые (динамические) данные, такие как системные журналы (логи в /var/log), базы данных, очереди печати и временные файлы почты.
/tmp — временные файлы, которые обычно удаляются при перезагрузке системы.
/dev — файлы устройств (здесь находятся точки доступа к жестким дискам, терминалам, звуковой плате, мыши и т. д.).
/proc — виртуальная файловая система, содержащая информацию о запущенных процессах и параметрах ядра «на лету».
/sys — виртуальная файловая система с информацией об оборудовании и возможностью его настройки через ядро.
/boot — файлы, необходимые для загрузки операционной системы (ядро Linux, образ initramfs, конфигурация загрузчика GRUB).
/mnt — временная точка монтирования для подключения внешних файловых систем и накопителей.
/media — точка монтирования для съемных носителей (флешек, внешних жестких дисков, CD-дисков), определяемая автоматически.
/opt — место для установки крупных сторонних приложений сторонних производителей (например, Google Chrome или тяжелое ПО).
/srv — данные для сервисов и служб, предоставляемых сервером (например, веб-файлы для сайта, если используется FTP или HTTP).
/lost+found — служебный каталог для восстановления поврежденных файлов после сбоя файловой системы (создается на каждом разделе отдельно).
23. Обфускация — это процесс намеренного запутывания программного кода, который делает его трудным для понимания человеком, но сохраняет полную работоспособность программы.
Зачем нужна обфускация.
Защита интеллектуальной собственности: скрывает уникальные алгоритмы и логику программы от конкурентов.
Предотвращение взлома: усложняет реверс-инжиниринг (обратную разработку) и поиск уязвимостей.
Защита от подделок: мешает злоумышленникам внедрить вредоносный код или создать пиратскую копию приложения (например, под Android или iOS).
Как это работает.
Обфускатор меняет понятный код автоматически:
Переименовывает переменные, классы и функции в бессмысленный набор символов (например, a, b, 123).
Удаляет все комментарии и форматирование.
Добавляет фальшивые ветвления и запутанные математические конструкции.
24. Пивотинг (Pivoting) — это метод, при котором специалист по безопасности (или хакер) использует уже взломанный узел внутри сети в качестве «моста» (или прокси) для атаки на другие компьютеры, которые изначально были недоступны из внешней сети.
Говоря простыми словами: если внешняя защита (файрвол) не пускает пентестера напрямую к базам данных компании, он сначала взламывает доступный снаружи веб-сайт, закрепляется на нем и уже оттуда (изнутри периметра) начинает сканировать и атаковать внутренние ресурсы.
Как это работает на практике.
Компрометация первой цели: пентестер находит уязвимость на сервере, который смотрит в интернет (например, корпоративный веб-сайт).
Создание туннеля: с помощью специальных утилит на взломанном сервере настраивается проброс трафика (туннелирование или VPN).
Разведка и продвижение: пентестер отправляет команды со своего рабочего места (например, из Kali Linux), они проходят сквозь взломанный сервер и попадают во внутреннюю изолированную сеть компании.
25. ICMP-туннель – скрытый канал для передачи данных, организованный между двумя узлами, использующий IP-пакеты с типом протокола ICMP (обычно echo request, echo reply).
Узлы обмениваются сообщениями echo request/echo reply, напоминающими работу утилиты ping, однако содержимое сообщений является информацией, передаваемой внутри канала. В случае, если оба узла имеют возможность принимать/отправлять запросы, передача может осуществляться любым узлом; в случае, если один из узлов находится за NAT'ом, только он может отправлять запросы (и получать ответы).
26. DNS-туннелирование (DNS tunneling) — это метод передачи произвольных данных и постороннего сетевого трафика поверх протокола DNS путем их кодирования в служебные запросы и ответы.
Как это работает
Маскировка под обычные запросы: Данные разбиваются на части и прячутся в именах поддоменов (например, ://example.com) в обычных DNS-запросах к серверам.
Обход ограничений: Сетевые экраны и фаерволы часто разрешают DNS-трафик (порт 53), так как без него не работает интернет.
Связь с сервером: Рекурсивный резолвер перенаправляет запросы на управляющий сервер злоумышленника или прокси, который собирает пакеты обратно в исходный файл или поток.
27. Command and Control (C2) сервер – это центральный узел или компьютер в сети, который злоумышленники или специалисты по безопасности используют для удаленного управления зараженными устройствами (ботами, агентами) внутри взломанной инфраструктуры.
Как работает C2-сервер
Связь с вредоносным ПО: после заражения компьютера вредоносная программа (агент) начинает периодически обращаться к C2-серверу (маячить), чтобы сообщить о своем присутствии.
Отдача команд: через этот сервер оператор отправляет приказы: скачать другие файлы, украсть данные, запустить шифрование или распространить атаку дальше в сети.
Получение данных: на C2-сервер стекается вся информация, которую злоумышленники смогли выкачать с атакуемого устройства.
28. Cyber Kill Chain — это модель информационной безопасности, которая описывает типичные этапы кибератаки от ее планирования до реализации.
Зачем нужна эта модель.
Остановка атаки на ранних стадиях: прерывая любое звено этой цепочки (например, блокируя доставку писем или зараженный файл в песочнице), можно предотвратить ущерб.
Понимание логики противника: помогает строить эшелонированную защиту под каждый этап.
Анализ инцидентов: дает единый язык для разбора уже совершенных атак.
Модель состоит из 7 последовательных шагов:
Разведка (Reconnaissance): Сбор информации о жертве (адреса сотрудников, технологии в компании, слабые места).
Вооружение (Weaponization): Создание вредоносного инструмента (например, эксплойта в связке с макросом в документе).
Доставка (Delivery): Передача вредоносного кода в периметр жертвы (фишинговое письмо, зараженная флешка).
Эксплуатация (Exploitation): Срабатывание вредоносного кода при уязвимости в системе.
Установка (Installation): Закрепление злоумышленника в системе (создание скрытого пользователя или бэкдора).
Управление (Command and Control / C2): Настройка канала связи между атакующей стороной и зараженным узлом для контроля.
Достижение целей (Actions on Objectives): Кража данных, шифрование файлов (вымогательство) или уничтожение инфраструктуры.
